сgroups — технология управления ресурсами системы
  изолирует системные ресурсы, такие как процессорное время и память
  
  core — реализует иерархическую организацию процессов
  controllers — отвечают за распространение ресурсов системы CPU, memory и др
  
namespaces - изолирует процессы на уровне ОС
  отвечает за то, чтобы каждый набор процессов видел только отведённый ему набор ресурсов ядра
  
  Пространство имён пользователей user
  Пространство имён идентификаторов процессов PID
  Сетевое пространство имён network namespace
  Пространство имён точек монтирования mount
  Пространство имён межпроцессного взаимодействия interprocess communication (IPC)
  Пространство имён UNIX Time-Sharing
    Позволяет на одной системе иметь независимые имена хоста и домена для различных процессов
    

          Чтобы запустить один процесс в неймспейсе или неймспейсах другого процесса, можно воспользоваться утилитой nsenter. 
          Это пригодится для запуска утилиты curl с хостовой системы в сетевом неймспейсе контейнера, если в 
          контейнере этой утилиты нет и добавить её туда нет возможности.

архитектура Docker
  
  Docker Host 
    Физическая или виртуальная машина с установленным Docker Engine, где выполняются контейнеры. 
    Хост служит основой для запуска и управления контейнерами, предоставляя им необходимые ресурсы и среду выполнения.
  
  Docker daemon, или dockerd
    Ядро Docker, служба, которая отвечает на API-вызовы и управляет Docker-объектами: контейнерами, сетями, хранилищами, образами.
    
  Docker Image
    Шаблон для создания контейнеров, неизменяемый образ, из которого разворачивается контейнер.
    
  Dockerfile 
    Файл-инструкция для сборки образа.

  Docker Registry
    Репозиторий для хранения и обмена Docker Images.

  Docker Container
    Контейнер, запущенный на базе образа изолированной среды, в которой работает приложение.

  Docker CLI
    Консольная утилита, которая позволяет взаимодействовать с Docker daemon — отправлять ему команды, создавать и управлять Docker-объектами.
    
docker run

  Docker ищет указанный образ в локальном кеше. Если образ не найден, он пытается загрузить его из удалённого репозитория.
  После загрузки образа Docker создаёт новый контейнер на основе этого образа.
  Контейнер запускается
  
  параметр -d 
    запускает контейнер в фоновом режиме

Образ (Image)
  код приложения, зависимости, конфигурацию, параметры окружения, команду для запуска основного процесса

Контейнер (Container)
  запущенный и готовый к использованию экземпляр образа
  
Dockerfile 
  конфигурационный файл с инструкциями, применяемыми при сборке Docker-образа и запуске контейнера
  
  Пример
  
      // Создаёт образ на основе Linux-дистрибутива Ubuntu 22.04.
      FROM ubuntu:22.04 
      // запускает команды
      RUN apt-get update && apt-get install -y nginx 
      // Копирует содержимое каталога myapp в каталог /usr/share/nginx/html .
      COPY myapp /usr/share/nginx/html 
      // Сообщает, что процесс в запущенном контейнере будет слушать порт 80
      EXPOSE 80 
      //запускать сам процесс Nginx соответствующей командой
      CMD ["nginx", "-g", "daemon off;"] 
  
  Инструкции FROM , RUN и ADD создают отдельные слои, или layers, итогового образа, 
  который содержит изменения файлов относительно предыдущего слоя
  
  
создание образа 
  переходим в директорию с Dockerfile и выполняем команду
    docker build -t mynginx .
  
Информация о слоях сборки
  docker image history <IMAGE ID>
  
Подробная информация об образе
  docker image inspect <IMAGE ID> или NAME
  
Создание и запуск контейнера из образа
  docker run --name nginx-container -p 80:80 mynginx:latest
  
При запуске контейнера будет создан еще один слой - файлы, изменённые в контейнере относительно образа, на базе которого он запущен


OverlayFS
  файловая система Linux. Она объединяет несколько слоёв в единую файловую систему, 
  управляет ими и сохраняет историю изменений в виде слоёв. 
  Образ в Docker — это упакованный набор слоёв.
  
  Каждый раз, когда вы выполняете инструкцию сборки Dockerfile, которая модифицирует (создаёт, удаляет, изменяет) файлы, создаётся новый слой OverlayFS.
  Каждый слой — это набор различий с предыдущим слоем.
  Если несколько образов используют одни и те же слои, то эти слои не дублируются, что позволяет более эффективно распоряжаться дисковым пространством.
  
  соответственно
    при удалении файлов размер контейнера не уменьшиться, т.к. будет создан новый слой без них
    
  Поэтому для хранения персистентных данных, а также для работы с часто изменяемыми данными:
    bind mounts, или точки монтирования
      монтирование папки хоста
      зависят от структуры файловой системы хоста и не управляются Docker напрямую
    volumes, или тома.
      Это именованная область в файловой системе хоста (/var/lib/docker/volumes/ в Linux), управляемая Docker, которая монтируется внутрь контейнера. 
    
  Tmpfs mounts — тома, создающиеся не на диске, а в оперативной памяти.
    
Монтирование
  docker run -d --mount type=bind,source="$(pwd)"/myapp,target=/app mynginx:latest
    type=bind - bind mount
    source - путь до папки хоста
    target - точка монтирования в контейнере
    
    аналогичный параметр -v "$(pwd)"/myapp:/app
    
  docker run -d --mount type=volume,source=appdata,target=/app mynginx:latest
    
    под виндой это будет папка с путем
      \\wsl.localhost\docker-desktop\mnt\docker-desktop-disk\data\docker\volumes\appdata\_data
  
    аналог (по умолчанию type = volume)
      --mount source=appdata,target=/app 
      -v appdata:/app
      
      
Сборка образа
  docker image build [OPTIONS] PATH | URL | - 
  
  OPTIONS — необязательные опции запуска команды;
  PATH | URL | - — контексты сборки образа.
  
  Если явно не указывать расположение Dockerfile, 
  то команда docker build будет пытаться найти файл с названием Dockerfile в директории контекста
  Чтобы указать другое расположение Dockerfile, можно использовать опцию -f <путь к Dockerfile> .
  
  Инструкция FROM <имя_образа>
    определяет базовый образ
  Инструкция RUN <command> 
    выполнения команд внутри контейнера во время сборки образа
  Инструкция COPY <путь_на_хосте> <путь_в_контейнере> 
    используется для копирования файлов и папок из файловой системы хоста в файловую систему контейнера
  Инструкция ADD
    аналогична COPY + может скачивать файлы по ссылке и распаковывать архивы
  Инструкция ENTRYPOINT
    указывает команду, которая будет выполнена при запуске контейнера
    если ENTRYPOINT не задан, то его значение — /bin/sh -c
  Инструкция CMD
    используется в качестве аргументов для ENTRYPOINT
    следует использовать как способ определения аргументов по умолчанию для команды ENTRYPOINT
    
    Итоговая команда запуска контейнера складывается из объединения инструкций ENTRYPOINT + CMD
    
      ENTRYPOINT ["/usr/bin/python"]
      CMD ["run.py"] 
    
    Переопределение параметров выполняемый при запуске контейнера
      docker run --command run2.py my-container
      или
      docker run my-container run2.py 
    
    но можно и без ENTRYPOINT
      CMD ["executable", "param1", "param2"]
        CMD ["/usr/bin/python", "app.py"] 
      
    
  Инструкция WORKDIR <path>
    устанавливает рабочий каталог для последующего выполнения инструкций
  Инструкция ENV <key>=<value> 
    для определения переменных окружения
    Переменные, определённые с помощью ENV , доступны в контейнере во время выполнения
    
    переопределение или добавление
    docker run --env VAR1=value4 nginx 
    docker run -e VAR2=value5 nginx 
  
  Инструкция ARG
    позволяет задать переменную, значение которой можно передать из командной строки в образ во время его сборки
      ARG IMAGE_VER=1.25
      FROM nginx:$IMAGE_VER 
      
      docker build --build-arg IMAGE_VER=1.26 . 
      
  Версионирование образов
    опции -t, --tag
    по умолчанию latest
      
      FROM nginx:1.25
      COPY index.html /usr/share/nginx/html 
      
      docker build --tag my-webserver:1.0.0
    
Оптимизация сборки
  слои кешируются в порядке указания в Dockerfile
  если изменен какой то слой = инструкция, то кеш начиная с него сбрасывается
  1. распологать в оптимальном порядке инструкции
  2. минимизировать количество инструкций (не писать 100500 RUN)
  
Безопасность
  Установка пользователя отличного от root
    RUN addgroup --system app \
      && adduser --system --group app \
      && chown -R app:app /app/
    USER app

  docker login [OPTIONS] [SERVER] 
  
  --username -u
  --password -p
  -password-stdin
    cat ~/my_docker_password.txt | docker login --username myusername --password-stdin 
    
  добавление тегов (ссылок) к образам 
    docker image tag SOURCE_IMAGE[:TAG] TARGET_IMAGE[:TAG] 
    или 
    docker tag ...
  
  скачивание образов из Registry
    docker image pull [OPTIONS] NAME[:TAG|@DIGEST] 
    @DIGEST - цифровая подпись образа
    
      docker pull alpine:3.19 
      docker pull alpine@sha256:c5b1261d6d3e43071626931fc004f70149baeba2c8ec672bd4f27761f8e1ad6b 
    
  загрузка образов в Registry
    docker image push [OPTIONS] NAME[:TAG] 
    
    
Docker Compose

  docker-compose.yml

      name: simple-python-app
      services:
        web:
          image: nginx:alpine
          ports:
            - "80:80"
          networks:
            - frontend-net
          volumes:
            - type: bind
              source: ./nginx/app.conf
              target: /etc/nginx/conf.d/default.conf
              read_only: true
          depends_on:
            - simple_python_app

        simple_python_app:
          image: simple_python_app:${APP_VERSION:-latest}
          build: ./simple_python_app
          environment:
            API_DB_HOST: db
            API_DB_PASS: apipass
            API_DB_NAME: api
            API_DB_USER: apiuser
          networks:
            - frontend-net
            - backend-net
          depends_on:
            db:
              condition: service_healthy
              restart: true

        db:
          image: postgres:16.2-alpine
          environment:
            POSTGRES_PASSWORD: apipass
            POSTGRES_DB: api
            POSTGRES_USER: apiuser
          volumes:
            - dbdata:/var/lib/postgresql/data
          networks:
            - backend-net
          healthcheck:
            test: ["CMD-SHELL", "pg_isready"]
            interval: 10s
            timeout: 5s
            retries: 10
            start_period: 30s
            start_interval: 1s

      networks:
        frontend-net:
        backend-net:

      volumes:
        dbdata:
