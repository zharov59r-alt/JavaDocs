Карты
  В DataLens нельзя вывести спутниковую карту, гибрид и дополнительные слои c Яндекс Карт.
  
  Легенда 
    Описывает обозначения, используемые на пользовательских слоях карты. 
  Подпись 
    Можно добавить на точки
    Подписями могут быть только числовые значения. Текст нельзя отобразить как подпись.
  Тултип
    Подсказка, которая отображается при наведении на объект. 
    В тултип можно выводить любые типы данных: текст, числа, даты из множества полей.
    
  Слои
    Создаваемые из геоточек
      точечный
      точечный с кластеризацией
        НЕ поддерживаются разные размеры отдельных точек.
        легенда НЕ поддерживается.
          Легенду можно сделать отдельным чартом и поместить на дашборд рядом с картой
            линейчатой диаграммой с агрегацией поля
              пример 09.P2 Практика - Общепит Москвы - Точки общепита — Легенда
        Подписи, тултипы и т.д. НЕ отображаются для кластерной точки
      полилинейный
      тепловой
    Создаваемые из геополигонов 
      полигональный
      
  порядок визуализации в рамках одной карты:
    Точечные карты (верхний слой)
    Полилинейные карты
    Полигональные (фоновые) карты
    Тепловые карты (нижний слой)
    
  Формат ГЕО
    (Широта, Долгота)
    
    GEOPOINT([lat],[lng])
    GEOPOLYGON("[[[55.79421,37.65046],[55.79594,37.6513],[55.79642,37.65133],[55.7969, 37.65114],[55.79783, 37.65098],[55.78871,37.75101]]]") 
    
    если координаты кривые, то можно распарсить
      первая координата: REPLACE(SPLIT([coord_str],',',1),'[','')
      вторая координата: REPLACE(SPLIT([coord_str],',',2),']','') 
      
      и потом в новом поле собираем в нужном порядке
      
Тепловая карта
  нет подписей, тултипов и настройки размера точек
  
Полилинейная карта
  для рисования тонких маршрутов или отображения связи между объектами
  
  Для работы с полилинейными картами в датасете каждая точка каждой полилинии должна храниться отдельной строкой. 
  В ней должны быть указаны:
    координаты точек линий;
    идентификатор каждой линии; - для группировки
    поле для сортировки порядка точек в каждой линии (например, timestamp или номер точки).

Оконные функции

  Агрегатная функция ( [поле] WITHIN или AMONG [поля для группировки] ORDER BY [поля для сортировки] TOTAL если нужно полное окно )

  параметры
    TOTAL — OVER()
    WITHIN — PARTITION BY
    AMONG — исключающее PARTITION BY
    ORDER BY
      работает в оконных функциях, направленных на расчёты нарастающих итогов 
      (RSUM, RCOUNT и другие с приставкой R) и «скользящих» функций (MAVG, MMIN и прочие с приставкой M).
    
  Все поля, которые используются в формулах оконных функций, должны присутствовать в чарте в явном виде
  не работают Итоги и Подитоги в чартах-таблицах
  Поле должно быть показателем
  
  Оконные функции можно последовательно оборачивать друг в друга и в другие агрегатные функции
    AVG(SUM([продажи] WITHIN [день])) 
    
    
    
LOD-выражения и вложенные функции
  LOD (level of details)— уровень детализации данных.
  Они определяют уровни детализации, на которые можно спускаться и над которыми можно производить вычисления, 
    не добавляя эту категорию в визуализацию.
  
  LODы работают с полями-измерениями, не включёнными в основную выдачу. 
  Основная и единственная задача LOD-выражения — задать набор измерений для вычисления показателя. 
  Оно определяет не окно вычислений, а уровень детализации данных, которые будут использоваться в расчётах.
  
  короче оно чем то похоже на подзапросы
  
  Параметр FIXED
    задаёт измерения для расчёта показателя вне зависимости от выбранных измерений в секциях чарта
    Если измерения не заданы, то расчёт выполняется без учёта каких-либо измерений
  
    SUM([Sales] FIXED)
  
  Параметр INCLUDE
    добавление измерений
  
    пример
      нужно посчитать сумму по неделям месяца и получить среднее для месяца
      при этом в таблицу выводятся только месяца и само полученное значение
      через оконку такое сделать неполучится потому что она требует вывода всех используемых полей, т.е. нужно выводить недели
      
      а через LOD можно, т.к. можно использовать измерения не выводимые в чарт
        AVG(SUM([SumSales] INCLUDE [Order Week]))
        
        аналог на SQL
          
        SELECT 
            OrderMonth,
            AVG(SumSales) AS AvgSalesPerWeek
        FROM
            (
              SELECT
                date_trunc("Order Date", “month”) AS OrderMonth,
                date_trunc("Order Date", “week”) AS OrderWeek,
                sum(t1."Sales") AS SumSales
              FROM table
              WHERE "Order Date" BETWEEN '2017-03-01' AND'2017-05-31'
              GROUP BY OrderMonth, OrderWeek
            )
        GROUP BY OrderMonth
  
  Параметр EXCLUDE
    противоположность INCLUDE
  
  
  Интересное
    
    вывести город с максимальным средним по продажам в день
    
      ARG_MAX(
        ANY([City] INCLUDE [City]), 
        AVG([Sales] INCLUDE [City],[Order Date])) 
        
      ARG_MAX( value, expression_to_maximize )
        Возвращает значение value, соответствующее максимальному значению expression_to_maximize
        
      ANY( value ) - необходимо т.к. в expression_to_maximize используется агрегатная функция
        Возвращает произвольное значение value из группы
        
      ВАЖНО в обоих функциях должно быть хотябы одно совпадающее измерение
      
    показать топ-N городов по продажам
    
      функции ранжирования (нумерации)
        RANK — возвращает порядковый номер строки с пропусками, если были выданы два одинаковых ранга;
        RANK_DENSE — возвращает порядковый номер строки без пропусков.
        
      через оконку
        RANK_DENSE(
          SUM(SUM([Sales]) WITHIN [City])
          )  
      
      через LOD
        RANK_DENSE(
          SUM(SUM([Sales]) FIXED [City])
          ) 
          
      и добавляем в фильтры
      
      а еще можно навернуть селектор и параметр 
        RANK_DENSE(
          SUM(SUM([Sales]) FIXED [City])
          ) <= [param]
      
      
Временные ряды
  AGO([measure], [date dimension], unit, number)
    рассчитывает показатель для даты/времени с указанием смещения
    
    measure — показатель (поле с агрегацией), обязательный аргумент;
    date dimension — поле с датой, вдоль него делается смещение по времени, обязательный аргумент;
    unit — единица измерения времени, на неё производится смещение: на год, месяц, день и так далее для аргумента number. 
      Принимает значения 'year', 'month', 'week' и т. д. Необязательный аргумент;
      default ‘day’
    number — число, на которое происходит смещение в единицах измерения, заданных аргументом unit. 
      То есть на сколько лет/месяцев/дней смещается. Может быть отрицательным числом, необязательный аргумент.
      default 1
      
    ago([Sales Now], [Order Week], 'week')
      
  AT_DATE(measure, date dimension, date_expr)
    посчитать значение метрики на конкретную дату
    
    AT_DATE([Sum Sales], [Order Date], DATETRUNC([Order Date], "month")) 
    
    
IGNORE DIMENSIONS

  если в чарте\запросе есть поле производная от поля в date dimension
  то функция ломается и выводяться null
  чтобы этого избежать, нужно использовать параметр IGNORE DIMENSIONS
  
  пример, выводится в таблице
    [Order Date]
    [Order Month] = datetrunc([Order Date], 'month')
    AGO([Sales Sum], [Order Date], 'month') - будет возвращать Null
    AGO([Sales Sum], [Order Date], 'month' IGNORE DIMENSIONS [Order Month]) - вернет корректные данные
      
      
BEFORE FILTER BY
  работает с агрегатными, оконными функциями LOD-выражениями
  
  ПОВЕДЕНИЕ
    при фильтрации данных, например через поле "Фильтры" происходит сначала фильтрация, а затем расчет функции
  
  BEFORE FILTER BY Поля
    Отключает предфильтрацию по указанным полям
  
  данная опция необходима для вычисления скользящих функций, т.к. для их расчета не должно быть фильтрации
  
  Скользящие функции
    производятся в динамическом (скользящем) окне, которое двигается вместе с точкой данных
    
    MSUM — скользящая сумма;
    MCOUNT — скользящий подсчёт количества значений;
    MAVG — скользящее среднее;
    MMIN — скользящий минимум;
    MMAX — скользящий максимум.
    
    MAVG(value, rows_1 ,rows_2 ….) 
      value — поле по которому производится вычисление
      rows_1 — нижняя граница, количество строк до текущей
      rows_2 — верхняя граница, количество строк после текущей
      
      
    Пример
      скользящее среднее по месяцам с окном шесть месяцев до и после
      строим линейную диаграмму по месяцам 
      
      MAVG(SUM([Sales]), 6, 6 ORDER BY [Order Month] ASC BEFORE FILTER BY [Order Month])
